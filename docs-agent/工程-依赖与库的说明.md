# 依赖与库的说明

此文件长期适用：记录环境与所用 crate。新增依赖时同步更新。

基于 2026-10-23 当时的做法，日后未必适用。

## 环境

Nix flake + rust-overlay。

工具链：stable 最新，附 `rust-src`、`rust-analyzer`、`clippy`、`rustfmt`（当前 rustc 1.99.1）。

用法：

```sh
nix develop
```

首次运行会生成 `flake.lock`，需提交。

cargo 已初始化：包名 `emcsync-cli`，edition 2024；`src/lib.rs` 放核心逻辑，`src/main.rs` 放 CLI 入口。`Cargo.lock` 入库。

nix flake 仍只提供 `devShell`，暂不提供 `packages.default`：等 CLI 骨架稳定后再补 `buildRustPackage`，免得每改一行代码就动 flake。

常用命令：`cargo build`、`cargo test`、`cargo clippy --all-targets`、`cargo fmt --check`。

## 依赖

分两步：先只接 Modrinth，跑通后再由人评判是否加 CurseForge。

记录大版本即可，小版本由 `Cargo.lock` 固定，且入库。

### 现在需要的

| 用途 | crate | 约束 |
| --- | --- | --- |
| CLI 解析 | clap 4 | `derive`；`suggestions` 默认开，负责拼写建议；`loader`、`platform` 用 `ignore_case` |
| HTTP | reqwest | 只启用 rustls，不启用 openssl，否则 Nix 构建要牵进系统库；配 tokio |
| 异步运行时 | tokio | `rt-multi-thread`、`macros` |
| JSON | serde / serde_json | `derive` |
| SHA-1 | sha1 | 小写十六进制，给 Modrinth 用 |
| 进度条 | indicatif | 非 tty 自动隐藏 |
| 交互确认 | inquire | 非 tty 会报错，用前先判 tty |
| 颜色 | anstream + owo-colors | 由 anstream 在管道、`NO_COLOR`、`TERM=dumb` 下去掉 ANSI |
| i18n | rust-i18n + sys-locale | 语言包用 YAML |
| 错误 | anyhow + thiserror | 应用层 anyhow，库层 thiserror |

落地时（2026-10-23）解析到的版本见 `Cargo.lock`：clap 4.6.7、reqwest 0.13.5、tokio 1.54.1、rust-i18n 4.2.4、sha1 0.11.0。

reqwest 0.13 的 feature 名与 0.12 不同：现在写 `rustls`（不是 `rustls-tls`），默认 provider 是 aws-lc-rs。实测在 devShell 里能直接构建，没牵进 openssl，也不用额外装 cmake。

不用 `walkdir`：只扫一层，`std::fs::read_dir` 足够。

### 暂不引入

- `murmur2`：只服务 CurseForge，随 CurseForge 一起延后。

## 已知约束

- 版本旗标不冲突：根命令 `-V/--version` 是 CLI 版本，`sync` 的 `-v/--version` 是 MC 版本，作用域不同。不要给 `sync` 加 `version`，也不要开 `propagate_version`，因此不需要 `disable_version_flag`。
- help 手写：clap 自动 help 关掉（`disable_help_flag`、`disable_help_subcommand` 设为 true，`arg_required_else_help` 设为 false 以免退回英文 usage），解析前扫 argv，命中 `help` / `-h` / `--help` 即按 locale 打印 `src/cli/help.rs` 的文本并退出。`help` 只在第一个位置算数，避免把名字叫 help 的目录当请求。
- clap 自身的错误消息仍是英文，只翻译常见几种（`src/cli/error.rs`）：未知子命令、无法识别的参数、缺少子命令、缺少必需参数、无效的值，带 `suggestions` 的建议一并翻译；其余原样交给 clap。
- 颜色统一走 `anstream::print!` / `anstream::eprint!`（`src/ui.rs`），管道、`NO_COLOR`、`TERM=dumb` 自动去 ANSI，样式用 owo-colors 生成。tty 判断用 `std::io::IsTerminal`，目前只留了 `ui::is_interactive` 给安装确认。
- Modrinth 要求唯一 `User-Agent`，形如 `github_username/project_name/version`。
- CurseForge 需要 `x-api-key`，无 key 一律 401。等决定接 CurseForge 时再定 key 的来源，不写进仓库。
- 安装目录固定为 `mods/`、`resourcepacks/`、`shaderpacks/`，缺失时随安装创建，且并入安装确认，不单独提问。
- 骨架阶段（2026-10-23）：CLI 收尾已完成；`sync` 仍只打印解析结果并报未实现，下一步接扫描与资源匹配。
- 本环境 `~/.cargo` 只读时，`CARGO_HOME` 可指到仓库内 `.cache/`（已过滤），只为跑通构建，不属于工程配置。
- 本环境 `TMPDIR` 可能指向已删除的 `/tmp/nix-shell.*`，doctest 建临时目录会失败；此时用 `TMPDIR=/tmp cargo test`。
- 提示文案都放 `locales/*.yml`（`help.*`、`error.*`、`sync.*`），`en.yml` 与 `zh-CN.yml` 要同时补齐；缺键会回落到 `en`。

## 新增依赖的做法

1. 在 crates.io 查最新稳定版，确认仍在维护。
2. 写入 `Cargo.toml`，用 caret 版本。
3. 在上表加一行，写清用途与关键约束。
4. 若该 crate 需要系统库，同步改 `flake.nix` 的 `devShell`。
